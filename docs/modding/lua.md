# Lua scripts

The game logic is mostly native code. Lua is used for start-up configuration, the menu framework, goals and rewards, the on-screen display and the automatic tests. There are 102 compiled scripts in `scripts/`.

| Area | Scripts |
|---|---|
| Boot scripts (`scripts/bootscripts`) | Choose the start state machine and set engine options with `BootOptions.Set`, `RenderOptions.Set`, `GUIOptions.Set`, `Plugins.LoadPlugin` and others. |
| `scripts/lua/gameconfig` | Game configuration values. |
| `scripts/lua/libraries/rewards`, `driveractions`, `drift`, `crazyspeed` | Fame and reward rules, driver action scoring, drift scoring. |
| `scripts/lua/libraries/socialgoals*` | Social goals and challenges. |
| `scripts/lua/libraries/osd`, `scripts/lua/mvc/*` | The on-screen display and the model/view framework of the menus. |
| `scripts/lua/weatherpresetlookup` | Weather presets. |
| `scripts/autotest/lua` | Scripts that drive the game automatically (start a race, switch to AI, change the camera). |

[lua-names.md](lua-names.md) lists the globals, calls and table keys the scripts use, with the scripts that use them. It is generated by `dcmod lua survey`.

## Reading a script

```bash
dcmod lua dis @scripts/lua/libraries/rewards.lua.bin
```

Each line has the instruction, the source line and the constant it refers to, for example `GETGLOBAL ... ; "Rewards"`.

## Changing a script

- **A value**: `lua.const` replaces a number or string constant, in the whole script or one function. It needs no Lua source, and it keeps the rest of the script exactly.
- **A whole script**: compile your Lua source with `dcmod lua compile` and put the bytecode in `files/scripts/...` at the same path. The game runs bytecode but crashes on Lua source it has to compile itself, so do not ship the source text under the game's script names. The compiled script can be decompiled with a tool such as unluac, which is not part of this kit.

## Scripts that run at start-up

A mod can list Lua files, supplied in its `files` folder, under `"scripts"`:

```json
{ "id": "me.hello", "scripts": [ "scripts/mods/hello/main.lua" ] }
```

When any mod lists scripts, the build replaces the game's boot scripts (`scripts/bootscripts/defaultbootscript.lua.bin` and `releasebootscript.lua.bin`, the two names the game's executable refers to) with a short Lua text. It runs the original boot script, kept beside it as `..._dcmod_original.lua.bin`, and then each mod script in load order, each in its own `pcall`, so a script that fails does not stop the others.

**Scripts are compiled when the mod is built.** The game runs Lua bytecode but crashes when it runs a chunk it has compiled from text itself (`loadfile` or `loadstring` of source), so the kit compiles each source script with the real Lua 5.1.5 compiler (included in the kit, MIT licence) and the boot script loads the compiled file. `dcmod lua compile file.lua` does the same by hand. A mod may also list a script that is already bytecode. Do not call `loadstring` or `loadfile` on source text in a mod script.

### Logging

The game's `print` does not write to the log. The boot script defines `dcmod.log(...)`, which does:

```lua
dcmod.log("lap time", t)      -- the log gets:  Mod: lap time 83.2
```

It works by opening a path that the runtime recognises (`dcmod/log/<text>`); capital letters are sent as `^` and the letter because the game lower-cases paths, and characters other than letters, digits and `" .:=_,-()[]"` become `?`. Up to 20000 lines are written per run. This needs the runtime of this release or later.

### The dcmod library

Every mod script can use these (all of them run the function you give inside a `pcall`, and a failure is logged as `Mod: error in ...` without stopping anything else):

| Function | Does |
|---|---|
| `dcmod.log(...)` | Writes a line to the game log. |
| `dcmod.after(seconds, fn)` | Runs `fn` once, in real time. |
| `dcmod.every(seconds, fn)` | Runs `fn` again and again. This is a mod's update loop. |
| `dcmod.on_ready(fn)` | Runs `fn` once the game is up: `dcmod.ready_delay` seconds (20) after the start. The game's event system does not exist before that, and using it earlier crashes the game. |
| `dcmod.setting(mod, name, fallback)` | The value of a setting the mod offers (see [mod-format.md](mod-format.md)); `dcmod.settings[mod]` holds all of them. |
| `dcmod.on(event, fn)` | Calls `fn(...)` whenever the game sends the event (after the game is up). `NewLap`, `GUIPushPage` and `GUIPopPage` are events the game's own scripts listen for; the others it sends are in [lua-api.md](lua-api.md). |

```lua
dcmod.on("NewLap", function(...) dcmod.log("lap", ...) end)
dcmod.every(10, function() dcmod.log("still running") end)
```

Timers, the boot hook, `dcmod.on` and `dcmod.log` have been run in the game. The arguments an event passes are not documented anywhere; log them to see.

### The car the player drives: `dcmod.car()`

`dcmod.car()` returns a table with the live state of the car the player is driving, or `nil` when no car is driven (in the menus, loading a race):

| Field | Meaning |
|---|---|
| `speed`, `kmh` | Speed in m/s and in km/h. |
| `rpm`, `max_rpm`, `limiter` | Engine speed, the highest engine speed and the rev limiter. |
| `gear` | 1 and up forward, -1 reverse. |
| `throttle`, `brake`, `steer` | What the controller gives: 0 to 1, 0 to 1, -1 to 1 (steering wheels are not read yet). |
| `wheels[1..4]` | Right front, left front, right rear, left rear: `load`, `lateral`, `longitudinal` (forces in N), `slip_ratio`, `slip_angle`. |

```lua
dcmod.every(1, function()
  local car = dcmod.car()
  if car then dcmod.log(math.floor(car.kmh), "km/h,", math.floor(car.rpm), "rpm, gear", car.gear) end
end)
```

Checked in the game (Ferrari 458 on Chile, 50 seconds of AI driving): speed went from 106 to 226 km/h, the gear from 3 to 6, and the front wheel load from 0 N in the air to 6800 N in a braking zone. The car is read through the same code as the telemetry output; the runtime installs it when a mods folder has scripts (the log says `a mod has scripts: the car state is available to them`).

How it works, for people who extend it: `dcmod.car()` calls `loadfile("dcmod/state/car.lua.bin")`. The runtime sees the path (`src/runtime_modapi.c`), writes a small Lua 5.1 chunk that returns the numbers into the user data folder and opens that file. The name must end in `.lua.bin`: the game's `loadfile` stops the game with an assertion for a path without it.

### What a script can use

All the globals the game's own scripts use exist when a mod script runs. [lua-api.md](lua-api.md) lists every global with its members, for example `Event.Listen`, `Event.SendEvent`, `Actor.GetPlayer`, `Actor.SpawnActor`, `GameState.StartGame`, `GUIOptions.Set`, `Rewards`, `Vehicles`, `Tracks`, `Tour`, `LAMS`, `HUD`, `Stats`. It was read from the running game. What each function takes is learned from the game's scripts: `dcmod lua dis` shows how they call them, and `dcmod lua survey` lists the calls.

### Finding out more

A mod script can walk any table and log it, which is how lua-api.md was made:

```lua
for k, v in pairs(Actor) do dcmod.log(k, type(v)) end
```
